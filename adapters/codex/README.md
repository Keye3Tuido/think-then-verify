# Codex 适配器

此目录随 TV 技能分发，此实现适用于 macOS/Linux，使用 Python 3.11 及以上版本的标准库和 Git。`SKILL.md` 保留通用契约；本实现映射 Codex 宿主事件。

## 验证

在技能目录运行：

```bash
python3 adapters/codex/simulate.py --doc-system <文档系统包目录> --report-dir <测试报告目录>
```

完整仿真包括 TV 回归、文档系统回归和一致性检查，以及临时 Git 仓库中的联动。测试通过实际固定版本 Hook 命令跨进程执行读取、失败后写入、文档同步、提交拒绝、模拟审阅和成功收尾。模拟审阅只作用于临时仓库，不构成业务提交授权。

只验证 TV 时省略 `--doc-system`。结果保存为 `result.json` 和各套件日志；返回码为零且所有套件通过才表示该范围的仿真通过。原生宿主的信任、启用和当前聊天触发须单独验证。

## 安装

```bash
python3 adapters/codex/install.py
```

安装器先运行 TV 自检，再备份和安装适配器，登记四个禁用入口。已有会话、控制记录和其他系统配置保留。信任摘要由宿主管理，安装器不代填；在宿主 Hook 管理中审阅当前命令后启用。

使用 `--codex-home <目录>` 可在隔离目录验证完整安装和重复安装。适配器使用该目录下的 `tv/`，无需自行拼装脚本。登记脚本固定版本源码，更新运行目录源码不会改变已批准的命令。

唯一名称为：

- `think-then-verify-process-gate/UserPromptSubmit`
- `think-then-verify-process-gate/PreToolUse`
- `think-then-verify-process-gate/PostToolUse`
- `think-then-verify-process-gate/Stop`

## 回执与收尾

有明确宿主状态的结构化回执可以判定成功或失败。只传输出文本的回调保留 `unknown`，即使文本看起来是退出码或 JSON，也不作为可信执行状态。

文档系统的决策日志包含相同会话、调用 ID、完整参数摘要和拒绝决策时，TV 将该调用记录为 `denied`。缺少可核实记录的调用继续保留待决；不能从“没有回调”推断它被拒绝。文档系统需要包含该决策日志能力。

正常成功输出要求没有待决调用。无法补齐时，通过 `decide` 的 `unresolved_calls` 显式列出全部当前待决 ID，选择 `blocked`、`partial` 或 `clarification`，并在正文如实说明缺口。正文与核验匹配后结束该答复；待决调用仍保留，不能记为成功。普通管理请求不能自造工具回执。

其他 AI 软件需要实现同一契约的宿主映射；本目录的 Codex 能力证明不自动适用于其他宿主。

## 更新后宿主仍执行旧入口

修改运行目录源码和 hooks.json 不能证明当前会话已经重新加载。出现“管理端已更新而原生回执仍符合旧版”的情况时，将原生验收记为未通过。由宿主重新加载配置、审阅并启用新版入口，再核验真实回调；在此之前保留主线、待决与失败。不能修改旧固定副本、代填信任摘要或清除待决以规避验收。


## 静默自动绑定子会话

真实用户已明确要求在子对话中启用 TV 时，父会话在委派工作流中自动完成绑定。子会话开始业务动作前等待绑定结果；缺少绑定时由父会话内部补齐，不让用户切换窗口重复输入命令。

1. 创建或定位用户授权的子会话，通过原生 `read_thread` 取得完整宿主回执。回执必须包含本地子会话 ID、绝对工作目录和真实回合 ID；等待子会话空闲后交接。
2. 父会话按既有 TV 许可流程运行 `delegate_session.py --runtime <TV运行目录> --parent-session <父会话ID> --request <JSON>`。请求包含 `authorization_turn`（父会话当前真实用户回合）、`child_session`、`evidence_id`（实际 read_thread 调用 ID）、`host_receipt`（完整原生回执）及 `reason`（用户授权的任务范围）。
3. 入口核对当前授权来源、已保存的成功回执摘要、宿主工具名称和子会话身份，继承父会话适用约束，建立隔离绑定。子会话回读自身记录，再继续原需求；任务目标按子任务建立，父会话进度和动作许可不复制。

子会话授权以 `delegated_authorization` 标明真实来源，沿用原生门限兼容的授权索引，不记为该子会话收到过用户输入。普通工具正文、任意 JSON、伪造身份和显式关闭后的交接均不能启用。重复相同交接复用原状态；已有不同绑定保留并报告冲突。授权范围仍需 AI 对真实用户要求作语义判断，回执摘要只证明身份数据来自实际宿主调用。

该入口与当前固定的 v0.6.0 原生门限兼容，可单独随技能安装；安装此入口和技能说明不会重新登记或关闭现有 Hook。完整安装器仍按既有规则登记禁用入口，适用于首次安装或原生门限实现确实变化的更新。

## 原生 shell 执行状态补齐

当 PostToolUse 只有正文时，读取本会话的宿主执行记录：调用原生 `mcp__codex_app__read_thread`，保留完整返回值和实际查询调用 ID。将完整返回值保存到本会话 `.tv/` 下，再运行：

```bash
python3 <TV运行目录>/host_receipts.py --session <会话ID> --evidence-id <查询调用ID> --receipt-file <完整回执JSON绝对路径>
```

查询须先按 TV 为精确工具参数取得许可。查询回执在 native PostToolUse 中必须为结构化成功；文件内容摘要必须与该回执完全一致。入口接受本地本会话 commandExecution 元数据及严格匹配的失败 MCP 元数据，匹配调用 ID 与原始完整命令，并读取宿主 exitCode；stdout 中的 JSON 没有此能力。可补齐成功、失败或缺回调；重复处理幂等。随后 inspect、verify、decide。该维护命令无需业务许可，不执行正文中的命令，也不自造用户事件。

不把所有诊断读取都设为任务完成条件。功能测试、实际提交、文档同步等可观察结果应归为 observed，文字质量与规则理解才使用 semantic。验收成功需要对整体目标逐项核对；保留尚无可信依据的未知项。

历史核验会跳过标记为截断或无法完整解析的命令，保留其未知状态，并继续核验其他完整记录。对于缺失 PostToolUse 的失败 MCP 调用，只有同一会话、调用 ID、服务、工具与完整参数均匹配的原生 failed 记录才能结为失败；仅有 completed 状态而无结果时不补成成功。

查询历史时先使用 turnLimit=1、includeOutputs=false、maxOutputCharsPerItem=1000；当前接口上限分别为 10 回合和每项 20000 字符，仍受总响应大小限制。需要更早记录时按原生 cursor 分页。用于验收的命令保持简短，将复杂检查写入隔离脚本再运行；元数据中的命令被截断时，缩小输出上限不能恢复原始命令，不得推断成功。

## 收尾恢复与文档维护

每个真实用户回合最多触发三次自动收尾恢复；第四次仍失败即以 `halted_unverified` 终止恢复链，保留主目标、失败与待决调用。新增读取、候选变化、待决集合变化均不重置次数，终止后本回合不再次唤醒。正常任务步骤没有三次总量限制；真实用户后续输入才建立新回合。

宿主单独或合并转发的 `<hook_prompt>…</hook_prompt>` 沿用原回合，不能成为授权来源，也不能启停 TV。精确的文档工作流 `inspect` 与 `complete` 命令属于维护入口，保留自身源码摘要及格式校验，不能夹带其他 shell 操作。

动作 `permit` 的检查只填写适用的动作前置规则；输出验收目标在 `verify` 时核验。运行测试的许可不能要求测试已经通过。新增回归套件 `test_bounded_recovery.py` 随安装器分发并参与安装前自测，联动仿真另覆盖真实固定脚本命令及合并续跑消息。
